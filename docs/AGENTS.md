# docs 文档站指令

## 基本要求

- 本目录是 VitePress 文档站.
- 回复和文档内容优先使用中文, 标点必须使用英文半角标点.
- 文档面向有经验的 Java 开发者, 默认读者了解 Java 和 Maven, 但不了解 Lava.
- 先读现有文档和对应源码, 再改文档. 不要凭空补 API, 方法名或行为.

## 首页

- 首页只写项目定位, 使用收益和模块概览, 不展开内部实现细节.
- 首页不要写 `Builder`, 具体参数, 异常细节, 底层实现类等内容.
- 首页 `hero.text` 保持短句, 避免 VitePress 默认 hero 把长中文标题拆得难看.
- 首页模块表第一列写具体模块名, 例如 `lava-core`, `lava-json`, `lava-http`.

## 模块 README

- 每个模块的 `README.md` 只做模块概览.
- README 保留依赖引入, 模块能力表和一个最小快速示例.
- README 不堆完整功能教程, 具体功能拆到独立子文件.
- 同一模块下的子文件不要重复写 `引入依赖`, 依赖说明只放在模块 README.

## 子功能文档

- 一个独立对外入口或一个独立功能, 可以拆成一个子文件.
- 不要机械地每个内部类都拆文件. 内部辅助类应归到对应入口文档里.
- 子文件结构推荐: 一句话说明, 最小可运行示例, 常用配置或核心用法, 常见坑与排查建议.
- 最小可运行示例需要包含完整 import 和入口类.
- 后续代码片段可以省略 import 和类定义, 只突出核心逻辑.

## 文件命名和链接

- 新增 Markdown 文件名必须使用英文 kebab-case, 避免中文 URL 影响分享.
- 文件名示例: `retry-util.md`, `io-util.md`, `duration-formatter.md`.
- 标题可以中英文结合, 例如 `# RetryUtil 重试执行`.
- 文档内链接使用相对路径, 例如 `[RetryUtil 重试执行](./retry-util.md)`.
- VitePress 侧边栏链接不写 `.md`, 例如 `/lava-core/retry-util`.

## 侧边栏

- 新增或重命名文档后, 同步更新 `.vitepress/config.mts`.
- 模块内侧边栏保持 `概览` 在第一项.
- 子功能页按常用程度排序, 不按文件名机械排序.

## 表格和排查

- 表格用于能力对照, 参数对照和异常排查.
- 表头不超过 5 列.
- 异常排查表必须包含: `异常/消息`, `原因`, `解决方式`.
- 技术术语, 类名, 方法名和配置键使用反引号.

## 验证

- 文档改完后执行 `npm run docs:build`.
- 如果构建只出现依赖包 Rollup 注释警告, 且最终 `build complete`, 可视为文档构建通过.
- 构建失败时先修链接, frontmatter 和 Markdown 语法问题.
