# JWT 算法选择

JWT 算法选择会影响密钥管理方式和多服务验签方案.

## 算法对比

| 算法    | 密钥形态                | 典型场景             | 建议                                 |
|---------|-------------------------|----------------------|--------------------------------------|
| `HS256` | 单个共享密钥            | 单体或内网少量服务   | 简单易用, 但签发方和验签方都持有密钥 |
| `RS256` | RSA 私钥签发 + 公钥验签 | 多服务分发公钥验签   | 生态成熟, 密钥管理清晰               |
| `ES256` | EC 私钥签发 + 公钥验签  | 高并发或追求更短密钥 | 性能和安全性平衡较好                 |

## 使用建议

- 单体应用或少量内网服务可以使用 `HS256`.
- 多服务只需要验签时, 优先考虑非对称算法.
- `ES256` 通常配合 `lava-crypto` 生成和读取 EC 密钥.

## 常见坑与排查建议

| 异常/消息            | 原因                           | 解决方式                     |
|----------------------|--------------------------------|------------------------------|
| 签发和验签算法不一致 | `HS256`, `RS256`, `ES256` 混用 | 固定签发端和验证端算法       |
| 多服务共享 HS 密钥   | 所有服务都能签发 token         | 多服务场景优先考虑非对称算法 |
| 密钥泄露             | 密钥硬编码或打印日志           | 使用 KMS 或配置中心管理密钥  |
